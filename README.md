# bilby in the browser

Run the [bilby](https://github.com/bilby-dev/bilby) examples in the browser
with [Pyodide](https://pyodide.org). See `PLAN.md` for the plan, `NOTES.md`
for background and `LOCAL-ONLY.md` for what is still tied to this machine.

## Where bilby comes from

The page offers several bilby versions, listed in `bilby-versions.json`
(currently 2.8.2, the default, 2.7.1, 2.6.0 and `main`), each pinned to a
commit of [bilby-dev/bilby](https://github.com/bilby-dev/bilby). The picker
in the header switches between them (it restarts Python and keeps the open
example, with any edits), and `?bilby=<name>` in the URL picks one.
`scripts/fetch-bilby.sh` takes both the examples (`examples/<name>/`, without
notebooks) and a bilby wheel (`wheels/`) from each version's commit, so the
examples always match the bilby that runs them. Neither is stored in this
repository. To move `main` to the current head:

```bash
scripts/fetch-bilby.sh --update
```

To add a version, add it to `bilby-versions.json` (with `pins` if it needs
older dependencies than `py/bootstrap.py` asks for, as 2.6.0 does for
dynesty), then run `scripts/fetch-bilby.sh` and `node scripts/lock-packages.mjs`.
Everything else (LALSuite, the other wheels, the page) is shared by all
versions.

## Other wheels

`wheels/` is generated, never committed:

- `scripts/build-igwn-segments.sh` rebuilds igwn-segments (needed by gwpy) as
  a pure-Python wheel from its sdist.
- `scripts/fetch-lalsuite.sh` downloads the LALSuite Pyodide wheel pinned,
  with its sha256, in `lalsuite-wheel.json` (a CI artifact of
  [colm.talbot/lalsuite](https://git.ligo.org/colm.talbot/lalsuite)). Set
  `LALSUITE_WHEELHOUSE` to serve a local build instead.

## Run locally

```bash
scripts/dev.sh
```

then open http://localhost:8000. Pick an example from the tree, edit it if you
like, and press Run (Ctrl/⌘+Enter). Stop restarts Python.

## Deployment

`.github/workflows/pages.yml` deploys every push to `main` to
https://colmtalbot.github.io/bilby-browser/. It runs the scripts above to generate
`examples/` and `wheels/`, then publishes
`index.html`, `app.js`, `worker.js`, `py/`, `wheels/` and `examples/`.

## Tests

```bash
npm install
npx playwright install chromium   # once
scripts/dev.sh                    # once, to generate examples/ and wheels/
npm test                          # every supported example in Node (test mode), every bilby version
npm test -- --bilby 2.6.0         # one bilby version
npm run test:browser              # Playwright smoke test of the page
python -m unittest tests/test_gwosc_range.py   # GWOSC range reads (needs gwpy==4.0.2)
```

Expected failures are listed with reasons in `tests/known-failures.json`,
for every version or for one. CI tests each version in its own job.
CI runs both before every deploy.

```bash
npm install

node scripts/test-examples.mjs core_examples/linear_regression.py
```

## Layout

- `index.html`, `app.js`: page, example tree, editor, output
- `worker.js`: Pyodide in a Web Worker; installs bilby, and LALSuite on the first GW example
- `py/bootstrap.py`: Python side, shared by the worker and the Node runner
- `examples/`, `wheels/`: generated, not committed (see above)
- `scripts/`: bilby fetch, example adaptation, igwn-segments build, dev server, manifest generator, Node runner
- `.github/workflows/pages.yml`: build and deploy to GitHub Pages
